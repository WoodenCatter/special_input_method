# Pad 文字沟通 v1

## 页面与 EEG 操作

首页「实时沟通」进入联系人列表。左右看在联系人与底部「返回主页」之间循环，咬牙确认；点选联系人也可进入通讯方式选择。通讯方式的「返回 / 输入法 / 视频通话」按当前扫描间隔自动循环，咬牙确认。视频入口仅提示即将开放。

输入法页面保留原有八组 T9 块、拼音、汉字、预测句与常用语。一级扫描在四个字母块之后依次高亮「返回 / 发送 / 删除」，咬牙或与当前扫描侧相同方向的信号执行。进入其他候选阶段后，同扫描方向信号跳过当前候选一项，反向信号改变扫描方向。左侧联系人可触屏切换。系统返回从输入法到通讯方式、再到联系人、最后到首页。

「+」打开邀请码页，邀请码仅由当前设备绑定的患者 profile 生成，可复制并交给家属端兑换。没有服务器 profile 或设备凭证时会显示配置提示。

## 协议和存储

接口基址为 `https://smu-brain.online/api/v1/chat`。聊天请求与 WebSocket 握手都携带设备 Bearer 和 `X-Chat-Profile-Id`。消息通过 HTTP POST 发送，WebSocket 仅收通知；重连后调用 conversations 与 `after_seq` 补拉，向前翻页用 `before_seq`。收到 `ping` 回文本 `pong`。

发送前用每条消息固定的 `client_message_id` 将待发消息写入当前 profile 的私有本地缓存；写入失败保留草稿。断网时保留待发状态，恢复后用原 ID 和原正文重试。服务端消息按 ID 去重，按 `server_seq` 排序。不同 profile 使用独立缓存键，切换 profile 会关闭旧 WebSocket 并清空活跃界面。

当前缓存使用应用私有 SharedPreferences JSON。若消息量增大，应迁移至 Room；此版本会随历史增长读写整个缓存。后台被系统杀掉后的即时推送不在本期范围。

## 手动验收

1. 在耳机设置配置设备服务器凭证并同步患者 profile；进入沟通页生成邀请码，家属端兑换。
2. 用两台不同 Wi-Fi 的设备互发文本；核对消息方向、时间、待发送状态、历史及未读数。
3. 断开 Pad 网络后输入并发送，确认显示待发送；恢复网络后确认仅出现一条已入库消息。
4. 关闭再打开沟通页，确认历史与未发送消息仍在；切换患者 profile，确认不会出现上一人的联系人或历史。
5. 用悬浮球与真实 EEG 分别遍历联系人、通讯方式、T9、发送、删除、返回；检查切页后旧扫描不再运行。
6. 视频通话入口只显示即将开放，不请求摄像头或麦克风权限。

最终 Gradle 同步、`./gradlew.bat assembleDebug`、`./gradlew.bat testDebugUnitTest` 及真机双端联调由项目维护者执行，本次未宣称这些步骤已通过。
